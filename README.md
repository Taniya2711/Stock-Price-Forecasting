# Stock Price Forecasting Using GBM and Heston Models

## Overview

This project implements and compares two stochastic models commonly used in quantitative finance for modeling and forecasting stock prices:

- Geometric Brownian Motion (GBM)
- Heston Stochastic Volatility Model

The project follows a two-stage approach. First, stock-price data is simulated to examine the assumptions underlying the models. The same framework is then applied to real historical Apple Inc. (AAPL) stock-price data from 2020 to 2024.

The analysis includes:

- Log-return analysis
- Statistical testing of model assumptions
- Volatility analysis
- Return-distribution analysis
- Autocorrelation analysis
- 30-business-day stock-price forecasting
- Monte Carlo simulation
- 90% prediction intervals
- Sharpe ratio calculation
- Comparison of GBM and Heston forecasts

The primary goal is to understand how different stochastic models represent stock-price behavior and, importantly, how they quantify uncertainty in future prices.

> **Disclaimer:** This project is intended for educational and quantitative-finance purposes. The forecasts generated by the models are stochastic estimates and should not be interpreted as investment advice.

## Models

### 1. Geometric Brownian Motion (GBM)

Geometric Brownian Motion is a classical stochastic model for stock-price dynamics.

The continuous-time GBM equation is:

$$
dS_t = \mu S_t\,dt + \sigma S_t\,dW_t
$$

where:

- $S_t$ = stock price at time $t$
- $\mu$ = expected annual return or drift
- $\sigma$ = annualized volatility
- $W_t$ = Wiener process

For simulation, the following discrete-time solution is used:

```math
S_{t+\Delta t}
=
S_t
\exp\left[
\left(\mu-\frac{1}{2}\sigma^2\right)\Delta t
+
\sigma\sqrt{\Delta t}Z
\right]
```

where:

```math
Z \sim N(0,1)
```

Here:

- $S_t$ is the stock price at time $t$.
- $\mu$ is the annual drift or expected return.
- $\sigma$ is the annualized volatility.
- $\Delta t$ is the time step.
- $Z$ is a standard normal random variable.

### GBM Assumptions

The classical GBM model assumes that:

- Log returns are normally distributed.
- Volatility is constant through time.
- Returns are independent over time.
- Price changes are continuous.
- Model parameters remain stable over the forecasting period.

The project explicitly tests some of these assumptions using statistical diagnostics.

---

### 2. Heston Stochastic Volatility Model

The Heston model extends GBM by allowing volatility to change randomly over time.

The stock-price process is:

$$
dS_t = \mu S_t\,dt + \sqrt{v_t}S_t\,dW_t^S
$$

while the variance process is:

$$
dv_t =
\kappa(\theta-v_t)dt
+
\sigma_v\sqrt{v_t}\,dW_t^v
$$

with:

$$
dW_t^S dW_t^v = \rho\,dt
$$

where:

| Parameter | Description |
|---|---|
| $S_t$ | Stock price |
| $v_t$ | Instantaneous variance |
| $\mu$ | Expected return/drift |
| $\theta$ | Long-run variance |
| $\kappa$ | Speed of mean reversion |
| $\sigma_v$ | Volatility of volatility |
| $\rho$ | Correlation between price and volatility shocks |

The main distinction between the two models is:

**GBM:**

$$
\sigma = \text{constant}
$$

**Heston:**

$$
v_t = \text{stochastic and time-varying}
$$

This makes the Heston framework more flexible for markets where volatility changes over time.

# Log Returns

For both simulated and real stock-price data, continuously compounded returns are calculated as:

$$
r_t = \ln\left(\frac{S_t}{S_{t-1}}\right)
$$

In Python:

```python
log_returns = np.log(stock).diff().dropna()
```

Log returns are particularly useful for stochastic models because they transform multiplicative price changes into additive return changes and make statistical analysis more convenient.

---

# Statistical Analysis

## 1. Normality Test

The project uses SciPy's `normaltest` to test whether log returns are normally distributed.

The hypotheses are:

$$
H_0: \text{Log returns are normally distributed}
$$

$$
H_1: \text{Log returns are not normally distributed}
$$

A significance level of:

$$
\alpha = 0.05
$$

is used.

---

## Simulated Data

The simulated data produced:

```text
Test Statistic: 1.4026
p-value: 0.4959
```

Since:

$$
p = 0.4959 > 0.05
$$

the null hypothesis is not rejected.

Therefore, there is insufficient evidence to conclude that the simulated log returns deviate from normality.

This result is consistent with the way the simulated data was generated.

---

## Real AAPL Data

For AAPL, the test produced:

```text
Test Statistic: 155.9211
p-value: 0.0000
```

Since:

$$
p < 0.05
$$

the null hypothesis of normally distributed log returns is rejected.

This indicates that the distribution of actual AAPL returns differs significantly from a normal distribution.

The empirical return distribution also exhibits relatively heavy tails compared with an ideal normal distribution.

This is an important limitation of the classical GBM framework.

---

# 2. ARCH / Heteroskedasticity Test

To investigate whether volatility changes over time, the project uses the ARCH test implemented through `statsmodels`.

The hypotheses are:

$$
H_0: \text{No ARCH effects}
$$

$$
H_1: \text{ARCH effects are present}
$$

ARCH effects provide evidence that the variance of returns is not constant and that volatility may be clustered over time.

---

## Simulated Data

For the simulated dataset:

```text
LM Statistic: 6.8247
LM p-value: 0.7419

F Statistic: 0.6802
F p-value: 0.7437
```

Both p-values are greater than 0.05.

Therefore, the null hypothesis is not rejected.

The simulated data does not provide significant evidence of ARCH effects.

This is consistent with the constant-volatility process used to generate the simulated data.

---

## Real AAPL Data

For AAPL:

```text
LM Statistic: 257.0639
LM p-value: 0.0000

F Statistic: 32.1026
F p-value: 0.0000
```

Both tests strongly reject the null hypothesis.

Therefore, there is strong evidence of ARCH effects and time-varying volatility in the historical AAPL returns.

This finding provides empirical motivation for considering a stochastic-volatility model such as Heston rather than relying exclusively on constant-volatility GBM.

# Volatility Analysis

The project calculates a 20-day rolling volatility of log returns:

```python
vol = log_returns.rolling(20).std()
```

The rolling-volatility analysis shows that AAPL's volatility changes substantially over time.

There are periods of relatively low volatility followed by periods of sharp increases in volatility.

This behavior is commonly referred to as **volatility clustering**.

The presence of volatility clustering is one of the main reasons stochastic-volatility models are useful in financial modeling.

---

# Return Distribution

The project visualizes the empirical distribution of log returns using:

- A histogram
- Kernel Density Estimation (KDE)

The real AAPL return distribution is concentrated around zero but exhibits noticeable tails.

This supports the statistical result from the normality test, which strongly rejects the assumption that AAPL log returns follow a normal distribution.

The analysis demonstrates an important difference between theoretical stochastic models and empirical financial data.

---

# Autocorrelation Analysis

The project calculates the autocorrelation function (ACF) of log returns for up to 30 lags.

The ACF is useful for examining whether current returns have a linear relationship with previous returns.

The results show that most autocorrelations of raw log returns are relatively close to zero, although a few individual lags exhibit deviations from zero.

This suggests limited linear serial dependence in daily returns.

However, low autocorrelation in raw returns does not imply that volatility is independent over time.

In particular:

```text
Returns
   |
   +--> Relatively low autocorrelation


Volatility / Squared Returns
   |
   +--> Can exhibit persistence
        |
        +--> Volatility clustering
```

This distinction is consistent with the simultaneous observation of relatively weak return autocorrelation and strong ARCH effects.

# Sharpe Ratio

The project also calculates the annualized Sharpe ratio.

The Sharpe ratio is calculated as:

$$
Sharpe =
\frac{\bar r-r_f/252}
{\sigma_r}
\sqrt{252}
$$

where:

- $\bar r$ = mean daily log return
- $r_f$ = annual risk-free rate
- $\sigma_r$ = standard deviation of daily log returns
- 252 = approximate number of trading days per year

For the real AAPL dataset, the resulting annualized Sharpe ratio was:

```text
0.787
```

The Sharpe ratio is included as a descriptive risk-adjusted performance measure and is not directly used to generate the stochastic forecasts.

# Stock Price Forecasting

Both models are used to generate a **30-business-day forecast**.

The models estimate their parameters from historical log returns and then simulate future prices.

The forecasting process can be summarized as:

```text
Historical Prices
       |
       v
Log Returns
       |
       v
Estimate Model Parameters
       |
       +-------------------+
       |                   |
       v                   v
      GBM               Heston
       |                   |
       +---------+---------+
                 |
                 v
        30-Day Forecast
```

The individual forecast paths are stochastic because they depend on random shocks generated during the simulation.

---

# GBM Forecast

The GBM model estimates annualized drift and volatility from historical log returns:

```python
mu_est = log_returns.mean() * days_per_year
sigma_est = log_returns.std() * np.sqrt(days_per_year)
```

The future stock price is then generated using the GBM equation.

The direct GBM forecast provides one possible future trajectory.

Because the future random shocks are unknown, a single forecast path should not be interpreted as a definitive prediction.

---

# Heston Forecast

The Heston implementation estimates the initial and long-run variance from historical returns:

```python
v0 = log_returns.var() * days_per_year
theta = v0
```

The following parameters are used in the simplified model:

```python
kappa = 1.0
sigma_v = 0.2
rho = -0.5
```

The variance process is simulated alongside the stock-price process.

The variance is constrained to remain non-negative:

```python
v_next = max(float(v_temp), 0.0)
```

This allows future volatility to evolve rather than remaining constant.

---

# Monte Carlo Simulation

Because stock-price forecasts are inherently uncertain, the project performs Monte Carlo simulation rather than relying on a single future path.

For each model:

```text
Number of simulations = 300
Forecast horizon       = 30 business days
```

For every simulation:

1. A random seed is initialized.
2. A GBM path is generated.
3. A Heston path is generated.
4. The resulting price path is stored.
5. The collection of paths is used to estimate the future price distribution.

The resulting simulation matrices contain:

```text
30 forecast days × 300 simulations
```

---

# 90% Prediction Intervals

For each forecast day, the project calculates:

- Mean simulated price
- 5th percentile
- 95th percentile

The interval:

```math
[P_{\text{5th percentile}}, P_{\text{95th percentile}}]
```

is used as an empirical **90% prediction interval** under the respective model.

These intervals illustrate the uncertainty surrounding the model's central forecast.

As the forecast horizon increases, uncertainty generally expands because more random shocks accumulate.

| Metric | GBM | Heston |
|---|---:|---:|
| Mean Final Price | 260.66 | 257.37 |
| Standard Deviation | 28.18 | 27.21 |
| Minimum | 207.59 | 175.98 |

### Interpretation

The mean final prices from the two models are relatively close:

```text
GBM Mean Final Price     ≈ 260.66
Heston Mean Final Price  ≈ 257.37
```

The median final prices are also similar:

```text
GBM Median     ≈ 258.29
Heston Median  ≈ 259.29
```

However, the distributions generated by the two models differ.

The central 90% range is:

```text
GBM     ≈ 92.85
Heston  ≈ 82.74
```

Therefore, in this particular Monte Carlo experiment, Heston produces a narrower 5th–95th percentile range around the central outcomes.

At the same time, the Heston simulations produce a lower minimum and higher maximum than the GBM simulations. This highlights that comparing models using only their mean or central interval can miss differences in their tails.

The important conclusion is not that one model is universally superior, but that **the choice of stochastic model affects both the forecast and the uncertainty distribution surrounding it**.

# Limitations

The current implementation is intended as a practical demonstration of stochastic financial modeling and has several limitations.

## 1. Simplified Heston Calibration

Some Heston parameters are manually specified:

```python
kappa = 1.0
sigma_v = 0.2
rho = -0.5
```

They are not obtained through formal calibration.

A production-level Heston implementation would typically estimate these parameters using historical data, option prices, or an optimization/calibration procedure.

---

## 2. GBM Assumptions Are Not Fully Supported by Real Data

The statistical tests show that real AAPL data violates two important assumptions associated with classical GBM:

- Normality of returns
- Constant volatility

Therefore, GBM should be viewed as a simplified benchmark rather than a complete representation of real stock-price dynamics.

---

## 3. Heston Implementation Is Simplified

The Heston model implemented in this project is a simplified stochastic-volatility simulation.

It does not include a complete market calibration procedure or sophisticated numerical techniques that are commonly used in professional derivatives-pricing implementations.

---

## 4. Historical Parameters May Not Remain Stable

The forecasting models estimate parameters from historical data.

However, market conditions can change over time, causing:

- Drift
- Volatility
- Correlation
- Mean-reversion behavior

to change as well.

---

## 5. No Transaction Costs or Market Frictions

The models do not account for:

- Transaction costs
- Bid-ask spreads
- Taxes
- Liquidity constraints
- Market impact
- Trading restrictions

---

## 6. Forecasts Are Stochastic

The future paths depend on random draws.

Consequently, different simulation seeds can produce different individual forecasts.

Monte Carlo simulation addresses this uncertainty by considering many possible paths rather than treating a single path as deterministic.

# Conclusion

This project presents an end-to-end framework for analyzing and forecasting stock prices using two stochastic models: **Geometric Brownian Motion and the Heston Stochastic Volatility Model**.

The initial analysis on simulated data demonstrates that the statistical testing framework behaves consistently with the assumptions used to generate the data. The simulated returns do not provide evidence against normality or constant volatility.

When the same analysis is applied to real AAPL data, the results are substantially different.

The normality test strongly rejects the assumption of normally distributed returns:

```text
p-value ≈ 0.0000
```

while the ARCH test strongly detects time-varying volatility:

```text
LM p-value ≈ 0.0000
F p-value  ≈ 0.0000
```

The results therefore demonstrate an important limitation of classical GBM when applied to real financial data.

The Monte Carlo analysis further shows that GBM and Heston generate different distributions of future prices. While their central forecasts are relatively similar in this experiment, their prediction ranges and tail outcomes differ.

Overall, the project demonstrates the importance of combining **financial modeling with empirical statistical analysis**. Rather than assuming that a theoretical model perfectly describes financial markets, the project evaluates the model assumptions against real data and examines how those assumptions influence the resulting forecasts.
